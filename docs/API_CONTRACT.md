# API contract

What the web app expects from the backend. It was written from the mock API of the first demo version (git tag `v0.1.0-priority1`, file `src/shared/mock/handlers.ts`), which behaves exactly as the real backend must. When both sides agree on this file, switching `VITE_USE_MOCK` to `false` needs no change in any page.

> **Status:** covers Priority 1 (auth, accounts, profile). Endpoints for horses, training, health and dashboards will be added as each phase is built.

## Conventions

| Topic | Rule |
|---|---|
| Base URL | `VITE_API_URL`, for example `http://localhost:3000/api` (NestJS backend) |
| CORS | While developing, the web app runs at `http://localhost:5173` and calls the backend on another port, so the backend must allow that origin |
| Format | JSON in, JSON out. Dates are ISO-8601 strings (`2026-09-21T08:30:00Z`) |
| Authentication | JWT. `/auth/login` returns `accessToken` (15 minutes) + `refreshToken` (7 days, 30 days with `remember`). The web app sends `Authorization: Bearer <accessToken>` on every call and trades the refresh token at `POST /auth/refresh` when it gets `401 UNAUTHENTICATED` |
| Session lifetime | Ends when the refresh token expires or is revoked (logout, password change, account locked); the API then answers `401 UNAUTHENTICATED` |
| Passwords | Never returned by any endpoint |
| Email format | Must end with `@gmail.com` (enforced by the web app and the mock on register, invite-staff and forgot-password) — reject anything else with `400 VALIDATION` / `400 INVALID_EMAIL` |
| Success | `2xx` with `{ "success": true, "data": <body shown in each table below> }`. The web app unwraps `data` |
| Error | Non-`2xx` with the body `{ "success": false, "code": "SOME_CODE", "message": "text", "data": { ... } }` |

### Errors every screen handles

| Status | `code` | Web app reaction |
|---|---|---|
| 401 | `UNAUTHENTICATED` | Opens the **Session Expired** modal |
| 403 | `FORBIDDEN` | Redirects to the **403** page |
| 0 | `NETWORK_ERROR` | Generated by the web app when the server cannot be reached |

Error `code` values are turned into readable English sentences by `src/shared/lib/messages.ts`.

## Authentication (public)

| Method | Path | Body | Success response | Errors |
|---|---|---|---|---|
| `POST` | `/auth/register` | `{ fullName, email, password, role }` — `role` must be `HORSE_OWNER` | `{ email, sentAt, expiresAt, resendAt }` | `400 VALIDATION` · `403 ROLE_NOT_ALLOWED` · `409 EMAIL_TAKEN` |
| `POST` | `/auth/verify-email` | `{ email, code }` | `{ email, fullName, role, requestCode, requestedAt, reviewer }` | `400 OTP_INVALID` (`data.attemptsLeft`) · `400 OTP_EXPIRED` · `404 OTP_NOT_FOUND` · `429 OTP_ATTEMPTS_EXCEEDED` |
| `GET` | `/auth/otp?email=&purpose=signup\|reset\|invite` | - | `{ sentAt, expiresAt, resendAt }` (feeds the countdown) | `404 OTP_NOT_FOUND` |
| `POST` | `/auth/otp/resend` | `{ email, purpose }` | `{ sentAt, expiresAt, resendAt }` | `429 OTP_COOLDOWN` (`data.resendAt`) |
| `POST` | `/auth/login` | `{ email, password, remember }` | `{ accessToken, refreshToken, expiresIn, tokenType, user }` | see the login table below |
| `POST` | `/auth/refresh` | `{ refreshToken }` | `{ accessToken, refreshToken, expiresIn, tokenType }` (the old refresh token is revoked) | `401 UNAUTHENTICATED` |
| `POST` | `/auth/logout` | `{ refreshToken }` | `{ success: true, message }` | - |
| `GET` | `/auth/me` | - | the user profile (same fields as `user`) | `401 UNAUTHENTICATED` |
| `POST` | `/auth/forgot-password` | `{ email }` | `{ sent: true, sentAt, expiresAt, resendAt }` — **same answer whether or not the email exists** | `400 INVALID_EMAIL` |
| `POST` | `/auth/reset-password/verify` | `{ email, code }` | `{ resetToken, expiresAt }` | `400 OTP_INVALID` · `400 OTP_EXPIRED` · `404 OTP_NOT_FOUND` · `429 OTP_ATTEMPTS_EXCEEDED` |
| `POST` | `/auth/reset-password` | `{ resetToken, password }` | `{ ok: true, activated }` — `activated: true` when an `INVITED` account set its first password (→ `ACTIVE`) | `400 RESET_EXPIRED` · `400 WEAK_PASSWORD` |
| `POST` | `/auth/accept-invite/verify` | `{ email, code }` — code from the invitation email | `{ resetToken, expiresAt, fullName, role }`; then call `/auth/reset-password` | `400 OTP_INVALID` · `400 OTP_EXPIRED` · `404 OTP_NOT_FOUND` · `429 OTP_ATTEMPTS_EXCEEDED` |

### Login errors

| Status | `code` | Meaning | `data` |
|---|---|---|---|
| 401 | `INVALID_CREDENTIALS` | Wrong email or password | `attemptsLeft` |
| 429 | `ATTEMPTS_EXCEEDED` | 5 wrong passwords; blocked for 15 minutes | `retryAt` |
| 423 | `ACCOUNT_LOCKED` | Club Manager locked the account | `fullName, roleLabel, lockedAt, requestedAt, reason` |
| 403 | `EMAIL_NOT_VERIFIED` | Status `PENDING_EMAIL` | same |
| 403 | `ACCOUNT_PENDING` | Status `PENDING_APPROVAL` | same + `requestCode` |
| 403 | `PENDING_INTAKE` | Status `PENDING_INTAKE` | same |
| 403 | `ACCOUNT_INVITED` | Status `INVITED` | same |
| 403 | `ACCOUNT_INACTIVE` | Status `INACTIVE` | same |
| 403 | `ACCOUNT_REJECTED` | Status `REJECTED` | same |

### OTP rules

6 digits · valid 10 minutes (invitation codes: 48 hours) · resend allowed after 60 seconds · 5 wrong attempts lock the code. Requesting a new code replaces the old one. The mock always uses `123456`.

## Accounts (requires `manageAccounts`)

| Method | Path | Body | Success response | Errors |
|---|---|---|---|---|
| `GET` | `/accounts` | - | `{ accounts: [PublicAccount] }` | `503 SERVICE_UNAVAILABLE` |
| `POST` | `/accounts` | `{ fullName, email, role }` — creates an `INVITED` staff account (not `HORSE_OWNER`) and emails an invitation code | `{ account }` | `400 VALIDATION` · `409 EMAIL_TAKEN` |
| `GET` | `/accounts/{id}` | - | `{ account }` | `404 NOT_FOUND` |
| `PUT` | `/accounts/{id}` | `{ fullName, phone }` — email and role cannot change here | `{ account }` | `400 VALIDATION` (`data.field`) · `404 NOT_FOUND` |
| `DELETE` | `/accounts/{id}` | - — only `INVITED`, `PENDING_EMAIL`, `REJECTED` (never used) | `{ ok: true }` | `409 CANNOT_DELETE_USED` · `409 CANNOT_CHANGE_SELF` |
| `POST` | `/accounts/{id}/approve` | - | `{ account }` — `PENDING_APPROVAL` → `ACTIVE`, emails the applicant | `409 INVALID_STATE` |
| `POST` | `/accounts/{id}/decline` | `{ reason? }` | `{ account }` — `PENDING_APPROVAL` → `REJECTED`, emails the applicant with the reason | `409 INVALID_STATE` |
| `POST` | `/accounts/{id}/lock` | `{ reason? }` | `{ account }` — `ACTIVE` → `LOCKED` | `409 INVALID_STATE` · `409 CANNOT_LOCK_SELF` · `409 LAST_MANAGER` |
| `POST` | `/accounts/{id}/unlock` | - | `{ account }` — `LOCKED` → `ACTIVE` | `409 INVALID_STATE` |
| `POST` | `/accounts/{id}/deactivate` | `{ reason? }` | `{ account }` — `ACTIVE`/`LOCKED` → `INACTIVE` (person left the club; records kept) | `409 INVALID_STATE` · `409 CANNOT_CHANGE_SELF` · `409 LAST_MANAGER` |
| `POST` | `/accounts/{id}/reactivate` | - | `{ account }` — `INACTIVE` → `ACTIVE` | `409 INVALID_STATE` |
| `POST` | `/accounts/{id}/resend-invite` | - | `{ account, sentAt, expiresAt, resendAt }` — new invitation code | `409 INVALID_STATE` · `429 OTP_COOLDOWN` |
| `PUT` | `/accounts/{id}/permissions` | `{ permissions: { <key>: true \| false } }` | `{ account, granted, revoked }` | `404 NOT_FOUND` |

`reason` is optional, at most 300 characters (`400 VALIDATION` otherwise); it is stored in `statusReason` together with `statusChangedAt` / `statusChangedBy`, and returned as `data.reason` when that account tries to sign in. Any status other than `ACTIVE` signs the account out of every device at once.

All of these answer `403 FORBIDDEN` when the caller lacks `manageAccounts`. The backend must also force the locked switches back to their required value (`normalizePermissions` — rules in `src/shared/lib/permissions.ts`, copied to the backend in `src/domain/permissions.ts`).

## Access-denied trail

| Method | Path | Body | Success response |
|---|---|---|---|
| `POST` | `/audit/forbidden` | `{ screen }` | `{ reference, managerName }` — writes an `ACCESS_DENIED` audit entry |
| `POST` | `/permission-requests` | `{ screen, reference }` | `{ ok: true }` — the user asks the Club Manager for access (an open request for the same screen is refreshed, not duplicated) |
| `GET` | `/permission-requests?status=OPEN|ALL` | - — requires `manageAccounts` | `{ requests: [{ id, at, screen, reference, status, resolvedAt, resolvedBy, account: { id, fullName, email, role } }] }` — default: only `OPEN` |
| `POST` | `/permission-requests/{id}/resolve` | `{ status: "GRANTED" | "DISMISSED" }` — requires `manageAccounts`; marks it handled (the permission itself is switched on in `/accounts/{id}/permissions`) | `{ request }` | `400 VALIDATION` · `404 NOT_FOUND` · `409 INVALID_STATE` |

## Data shapes

```ts
type Role = "HEAD_TRAINER" | "VETERINARIAN" | "GROOM" | "HORSE_OWNER" | "CLUB_MANAGER";

type AccountStatus =
  | "PENDING_EMAIL" | "PENDING_APPROVAL" | "PENDING_INTAKE" | "INVITED"
  | "ACTIVE" | "INACTIVE" | "REJECTED" | "LOCKED";

type PermissionKey =
  | "viewHorses" | "editHorses" | "deleteHorses"
  | "createPlan" | "assignSchedule" | "recordMetrics" | "ackAlerts"
  | "viewMedical" | "placeLock" | "liftLock"
  | "manageAccounts" | "viewAudit";

interface PublicAccount {            // never contains a password
  id: string;
  fullName: string;
  email: string;
  phone: string;
  role: Role;
  status: AccountStatus;
  createdAt: string;                 // ISO
  lastActive: string | null;
  requestedAt: string | null;        // when the sign-up request was sent
  requestCode: string | null;        // REQ-2609-014
  lockedAt: string | null;
  invitedBy: string | null;          // Club Manager who invited this staff account
  statusReason: string | null;       // reason of the last decline / lock / deactivate
  statusChangedAt: string | null;
  statusChangedBy: string | null;
  permissions: Record<PermissionKey, boolean>;
  permissionsChangedAt: string | null;
  permissionsChangedBy: string | null;
  notify: Record<"thresholdAlert" | "lockLifted" | "dailyDigest" | "raceResults", boolean>;
}
```

The source of truth for these types is `src/shared/types/auth.ts` (git tag `v0.1.0-priority1`).

## Financial billing and actionable trainer overview (2026-11-05)

### Financial invoices

FinancialInvoice adds nullable boardingDays (integer), boardingMonthlyRate (number in API; Decimal in DB), and dueAt (ISO timestamp). Legacy invoices retain their existing amounts and null snapshots/deadlines. InvoiceStatus DRAFT is unchanged in storage; UI displays Not issued / Chưa phát hành.

POST /invoices/generate-monthly accepts { billingPeriod: "YYYY-MM" } for a completed calendar month only. It creates one unissued invoice per horse/current owner/period with recorded occupancy; existing invoices of any status are preserved. Concurrent generation uses serializable transactions with bounded conflict retries. Monthly generation runs at 00:10 UTC+7 on day 1 for the previous month. Managers can use the same endpoint to recover a missed month; the scheduler does not backfill all historical periods.

Boarding = round(6000000 × unique occupied club-calendar days / days in month), rounded once to VND. Arrival counts, departure does not, same-day stays count once, overlapping transfers do not duplicate days. New invoices snapshot the day count and monthly rate. POST /invoices calculates boarding server-side rather than trusting a client amount; PATCH cannot change the fee/period of calculated snapshots. Other fee rules are unchanged, including the existing 4000000 training default on monthly generation. Current ownership is used because there is no historical ownership ledger; managers must reconcile ownership transfers before issue.

First issue DRAFT → SENT sets dueAt = now + 7 days; reissue preserves it. The same rule applies to direct creation/update into SENT. A minute sweep and report reads mark only SENT invoices with dueAt < now and netAmount > 0 as OVERDUE. No late penalty; payInvoice still accepts owned SENT/OVERDUE invoices. Existing PAID invoices cannot be edited/reopened. Old invoices without a deadline are not retroactively made overdue.

GET /invoices/owner-summary adds outstandingDebt: the sum of positive netAmount for SENT + OVERDUE invoices. PAID, DRAFT, CANCELLED, and club payouts are excluded; owner isolation remains enforced by the controller.

Errors: INVALID_BILLING_PERIOD, BILLING_PERIOD_NOT_CLOSED, INVALID_STAY_INTERVAL, BOARDING_FEE_READ_ONLY. Generate-monthly validates its DTO at the HTTP boundary.

### GET /training/overview

Existing kpis and rows are preserved. Two top-level objects are added, both null when absent:

- nextWorkout: { id, planId, horseId, horseName, horseCode: string|null, workoutType: string|null, scheduledDate: ISO, intensity: string|null, surface: string|null, status }. Nearest SCHEDULED session strictly after now, under an ACTIVE plan for a managed horse. Ordered by scheduledDate ascending then id ascending; later days are included.
- latestPlan: { id, planCode: string|null, name, horseId, horseName, status, startDate: ISO, endDate: ISO, currentPhaseName: string|null }. Most recently updated ACTIVE plan for a managed horse, stable id tie-break. Current phase is selected by inclusive UTC+7 calendar-date boundaries.

Trainer UI links to /training/calendar and /training/plans/:id, with an empty-state link to /training/plans/new. No polling, visibilitychange listener, or seven-day schedule matrix is added.
